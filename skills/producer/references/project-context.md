# 项目条件与研究

## 条件从哪里来

先理解这次工作要产生什么效果，以及谁使用成果。项目条件可以来自明确委托、既有作品、使用环境、受众研究、测量数据、适用规则与个人偏好。它们的依据不同，不能互相冒充。

对会影响执行的要求，保留其内容、来源、适用范围，以及何时可能失效。硬性要求需要可靠依据和当前适用性；观察结论需要知道样本和观察条件；偏好须确实由相关人表达；助手推断标为暂定，不能静默变成既定决定。

研究不仅寻找“大家都这样做”的形式。围绕用途调查受众处境、使用路径、媒介限制、可比案例和已有效果。既检查共性也检查反例，解释为何这些发现适用于当前项目。样本中的常见风格不自动成为该平台或行业的唯一标准。

## 落实为项目约定

AGENTS.md 保留反复执行需要知道的目的、边界、交付要求、重要约定和可靠材料位置。篇幅较大的研究、具体稿件、数据和版本记录放在独立项目文件，AGENTS.md 指向它们；避免把完整研究和所有任务历史抄进入口。

新规则要能改变具体判断或行动。写明哪些条件必须满足、哪些是研究支持的选择、哪些仍可试验。项目事实变化或新证据推翻原假设时更新，并保留必要的变更缘由。不要把存在争议的结论伪装成格式上的硬条件。

需要专业判断时直接委托相应能力。执行者读取这些项目条件，专业 Skill 决定如何使用它们。项目条件不需要另一个管理角色解释后才能到达专业工作。

## 保持授权与能力真实

用户允许的行动、禁止的行动和待决定事项属于项目。沿用有效授权，不能因内部流程要求用户重复许可，也不能根据正面评价推定新的外部操作权限。核实当前工具和权限，不把运行环境尚未提供的能力写成承诺。

个人资料位置、工作目录、发布账号和恢复规定采用宿主及用户提供的实际约定。通用 Producer 不硬编码任何人的文件路径、项目注册表、账号或平台。
